# Media / desktopIntegration / fileAssociations リファクタリング実装計画

**前提:** [設計仕様](../specs/2026-11-21-media-desktop-integration-design.md)

**受入方針:** 責務と新 API の契約を優先し、旧動作の完全再現・互換 API の併存は要求しない。各 Phase の管理対象構成は成立させ、意図的な変更と移行先を記録する。

## 着手前の基準チェック

現行の `desktop-integration-home` Fixture は Kitty の参照する Catppuccin オプションを宣言していないため評価が停止するとのレビュー報告がある。通常の Home 入口または必要な Catppuccin モジュール・引数を備えた Fixture に修正し、移行前の基準チェックを再実行する。Kitty 本体の設定をテスト都合で削除しない。treefmt と評価・ビルド・実行テストの失敗は区別する。

## Phase 1 — mpv の独立化

**対象:** `nix/modules/home/programs/mpv/default.nix`（新規）、`nix/modules/home/features/media.nix`。

- `media.mpv.settings` を Program に移し、`autofit-large` を `autofit-larger` に修正する。旧オプションは移行先を示すエラーにする。
- `programs.mpv.finalPackage` を実効実行ファイルとして扱い、`scripts` や package 上書きも反映する。
- 生成 `mpv.conf` の読み込み結果について、終了コードだけでなく `Error parsing option` を検査する。単独利用と `package = null` も確認する。

## Phase 2 — Session Provider・Browser 選択・FileChooser・Portal

**FileChooser の調査結果と受入ゲート:** Home にユーザー向け API と backend 提供を集約し、NixOS / Session Provider が Portal 本体とシステム既定 GTK 等を所有する設計を採用する。レビューの隔離 D-Bus / Xvfb では GTK アプリから Home backend の起動・空白入りファイルの返却まで成功し、D-Bus サービス定義を外すと選択済みでも OpenFile 応答 2 / URI 空となった。実 NixOS / Niri の systemd ユーザーサービス起動は未検証なので Phase 2 の受入で実セッションのファイル返却まで確認する。Phase 1 は独立して着手可能。

**対象:** `nix/modules/home/features/desktop-integration/`、`nix/modules/nixos/features/desktop-integration.nix`、`nix/profiles/variants/desktop-integration/{home,nixos}.nix`、`nix/modules/{home,nixos}/features/session-gui.nix`、内部 Session Provider、`nix/modules/home/programs/{glide,firefox,qutebrowser,krita}/`、`nix/modules/home/programs/niri/`、GUI Profile、`media.nix`、`nix/tests/{home,nixos,system}/desktop-integration.nix`、`nix/tests/home/desktop-integration-wrapper.nix`。

- **新 FileChooser API に直接切り替える。** `desktopIntegration.fileChooser.mode`（auto / terminal、既定 auto） を Home のみに導入し、旧 `portal.fileChooser.backend` の設定を新 API へ移行して撤去する。`auto` は backend・追加パッケージ・専用ラッパー・強制設定に寄与しない。`terminal` は対応 Provider とセッション適用先を明示要求し、提供不能なら理由付きエラー。system variant と fileChooser.enable は導入せず、auto が委譲・無寄与を担う。旧 termfilechooser は terminal、旧 gtk / null は auto に移行し、明示 GTK が必要なら低水準 Portal 設定を使う。Terminal の有無で chooser を暗黙に選ばない。GUI Profile なし・Media-only・Terminal OFF の Home で desktopIntegration / Glide / fileAssociations が暗黙に要求されず、Media が単独で成立することを確認する。GUI Profile は Media と desktopIntegration を個別に有効化し、Glide を既定選択する。fileAssociations は Phase 3 で Profile に追加する。同じ Phase で Browser Provider と `desktopIntegration.browser.selected`、`media.graphics.krita.enable` を導入し、Linux GUI / TTY の新契約を検証する。 旧 `desktopIntegration.portal.enable` も Home / NixOS から撤去し、Host / Profile / Fixture の参照を新契約に移す。FileChooser と明示ポリシーは独立して寄与し、上流 `xdg.portal.enable` は Portal 所有者が管理する。旧スイッチによるラッパー・backend 選択の隠れた停止条件を残さず、Home の明示 terminal と auto の受入ケースを確認する。NixOS の旧 FileChooser 選択・専用 backend 設定と Profile の関連寄与を撤去し、必要な利用者選択を Home に移行する。上流 NixOS xdg.portal.* は維持する。
- **Portal Service とユーザー backend の所有者を分離する。** NixOS / Session Provider は Portal 本体・標準 backend を提供し、Home はユーザー backend を提供する。Home の `xdg.portal.enable = false` を維持し、`extraPortals` の属性だけに依存しない。Niri OFF・外部 backend なしの独立 NixOS、独立 Home の auto / Media-only / Terminal OFF では Portal 本体と空 extraPortals の組合せを新たに要求しない。全 assertion を確認する。Host / 他 Feature の既存基盤を保持し、TTY では GUI Portal を要求しない。 Niri ON の管理対象統合構成で Home の明示 terminal と NixOS `xdg.portal.enable = false` を組み合わせ、Home Manager が NixOS の実効構成（osConfig 等）を参照して理由付き assertion に到達することを確認する。auto または desktopIntegration 全体 OFF は本体を要求しない。GNOME backend のみで GTK が未提供でも auto は GTK を要求せず評価できることを確認する。独立 Home ではホストが Portal 本体・起動基盤・標準 backend を提供する前提を明記し、参照できない NixOS の構成を仮定しない。
- **Home の FileChooser 提供と実動作を検証する。** Niri ON / useNautilus=false の NixOS GTK 既定を維持し、旧無条件 mkForce と NixOS 側の明示 FileChooser 選択用優先度上書きは撤去する。Home terminal は backend パッケージ、.portal、D-Bus サービス、systemd user unit、探索経路、選択ポリシー、Yazi ラッパーを提供する。NixOS / Niri の実セッションで systemd ユーザーサービスから backend が起動し、GTK アプリで Kitty 上の Yazi が選択した空白入りファイルの URI が返るまで検証する。D-Bus サービス定義を外す負のテストで選択ログだけでは合格しないことを確認する。Home auto は専用 backend・ラッパー・選択設定を寄与せず、セッション既定に委譲する。NixOS と Home の暗黙同期、外部ラッパーによる補完は対象外。 両側の移行完了後は `systemctl --user show` 等で実効 unit の FragmentPath / ExecStart と実プロセスを確認し、Home の選択したパッケージが起動したことを証明する。URI 返却のみでは合格としない。移行案内は組み込み Home Manager では既存の u 等のシステム切替一回で両側を更新し、独立 Home でのみシステム側の旧 backend・登録撤去 → Home の更新の順とする。いずれも更新完了後に OS を再起動して実効 unit / ファイル返却を確認する。u の実装は変更しない。混在世代の動作保証・互換レイヤー・独自の unit 優先順位制御は設けない。
- **FileChooser の設定変更の反映時期を検証する。** 構成切替直後の稼働中 Portal / D-Bus / systemd への即時反映は要求しない。独自の再読込・自動再起動機構は導入せず、移行案内は OS 再起動を反映保証の条件とし、個別サービスの手動操作手順は記載しない。実 NixOS / Niri で auto → terminal（ユーザー D-Bus サービスディレクトリが未作成の初回も含む）と terminal → auto の構成切替・生成物更新を行い、各更新後に OS を再起動する。初回 terminal は backend が停止状態であることと D-Bus 登録情報・systemd unit の解決を確認し、GTK アプリの OpenFile による backend 起動・ファイル返却・Home の実効 ExecStart まで検証する。auto に戻した場合は Home の旧寄与がなくなり、管理対象 Niri の標準 chooser が使われることを確認する。固定版 dbus-broker 37 の新規サービスディレクトリの発見問題をこの受入で検出する。
- **Portal の設定出力を Service 有効化から分離する。** NixOS が Portal 本体を管理し Home の `xdg.portal.enable = false` でも、dotfiles が明示的に管理する Home のポリシーは指定先の設定ファイルに出力する。管理対象 Home は Portal 本体を重複提供せず、同一ファイルの二重生成を避ける。Niri の `Secret=none`、`Access`、明示 FileChooser 等の同一管理対象ファイルへの寄与を保持し、`auto` では FileChooser のキーを追加しない。生成物を確認し、管理対象の適切な隔離 D-Bus 環境で明示 chooser の動作を検証する。 Home の未要求ポリシー（default / Access / Notification / Secret 等）は出力しない。NixOS GTK + Home auto / Secret=none の Fixture で Home の生成物が Secret のみ（FileChooser と暗黙の default なし）であり、NixOS の標準選択を尊重することを確認する。Home terminal + Secret=none のケースも検証する。Portal の探索・解決を再実装しない。 選択結果だけでは UseIn フォールバックによる偽陽性を排除できない。Home の明示 FileChooser 規則による選択経路と Home の Secret=none の実効適用を独立に検証し、各設定を除去した負の Fixture または選択ログで設定が欠ければ検出できることを確認する。NixOS 側ではシステム既定 GTK の保持を検証する。
- **Portal の探索・解決は upstream に委譲する。** 共通 `portals.conf` と `niri-portals.conf` にそれぞれ明示した設定が各ファイルに出力され、共通の `Secret=none` 等を固有ファイルへ自動転記しないことを確認する。別ファイル・別ディレクトリの実効ポリシーの完全保持、管理外ファイルの探索・自動統合・独自 activation 事前検査は受入条件としない。通常の Nix / Home Manager の同一ファイル衝突処理を利用する。
- **Niri を Session Provider 化する。** `sessionGui.session` を維持し、Home の Niri Program 要求と NixOS の Niri 有効化・既存 `sessions.niri` の起動情報を小さな内部 Provider にまとめる。Niri Program 固有設定は維持する。Home / NixOS の各評価環境で必要な提供状態、Portal の出力先、NixOS ではセッション名と起動コマンドを選択 Provider から取得し、Greeter / Portal に Niri 固有条件を分散させない。sessionGui OFF では実効 Provider なし。Linux Home の明示 terminal は実効 Provider がなければ理由付きエラー、auto は成功する。他 Feature を暗黙に有効化しない。Niri ON / OFF、独立 Niri Program ON + sessionGui OFF、Greeter の選択情報、Portal の出力先を検証する。Consumer が選択 Provider の情報に従うことは内部のテスト用 Provider データ等で確認し、Sway / Hyprland の実装や外部セッション対応を要求しない。独立 desktopSession.id、外部セッション宣言、共通 Registry は設けない。 NixOS Provider の `programs.niri.enable` 要求を `lib.mkDefault true` とし、既存 mkForce false に加え Host の通常 `false` で定義衝突ではなく理由付き Session Provider assertion に到達する回帰テストを追加する。
- Niri の固定 Glide 起動を選択 Provider のコマンドに置き換える。desktopIntegration OFF、選択 `null`、Niri 単独で起動行がないことを確認し、**肯定ケースとして `browser.selected = "qutebrowser"` を追加**する。生成 `config.kdl` の `spawn-at-startup` が選択 Provider の最終実行ファイルを参照し、Qutebrowser の起動行が**正確に1回**、Glide の固定起動行が**0回**であることを確認する。単純な `glide` 行の有効化条件付けだけではテストを通さない。
- Glide の `mkDefault` は GUI Profile / Host の選択としてのみ適用する。Media の有効化だけでは Browser を要求しない。desktopIntegration 単独で Browser 未選択なら `selected = null` とし、Browser を要求しない。Host / Profile で意図した Browser を選択する設定へ移行し、旧 Program フラグの組み合わせから選択順を再現しない。新選択 API、明示 `null` / 別 Provider、選択 Provider の提供と起動コマンドを検証する。 Qutebrowser の現行 `programs.qutebrowser.enable = true` は通常優先度なので、個別 Provider の有効化要求を `lib.mkDefault true` 等の適切な既定優先度にする。Qutebrowser 選択時に Host が `programs.qutebrowser.enable = false` を明示すると、強制上書きや同優先度の定義衝突ではなく Browser Provider の理由付き assertion に到達することを検証する。
- MIME の所有者切替は Phase 3 にまとめる。Phase 2 では旧 MIME API の全置換動作や複数 Feature の候補順を新たに再現する互換処理・専用テストは追加しない。
- **`desktop-integration-wrapper` を新 API へ直接移行する。** Fixture に `fileChooser.mode = "terminal"` と `sessionGui = { enable = true; session = "niri"; };` を明示し、Kitty・Alacritty・WezTerm と Yazi の実行経路を検証する。`auto` では自身の専用ラッパー・FileChooser 選択を追加しないことを確認する。
- Darwin の Glide・ff2mpv 旧経路は維持する。Linux で無効になった `media.programs` の明示設定は移行エラーにする。

## Phase 3 — 独立 fileAssociations Feature と Linux adapters

**対象:** `nix/modules/home/features/media.nix`、`nix/modules/home/features/file-associations/`（新規、内部 Linux adapter 含む）、`desktop-integration/{mime-apps,portal,termfilechooser}.nix`、Feature の import / Profile 構成、Browser 共通設定、関連テスト、`nix/modules/home/programs/{yazi,mpv}/default.nix`、`nix/modules/home/features/terminal.nix` と Terminal Provider。

- **`fileAssociations` を独立した公開 Feature として実装する。** `media.fileAssociations.*` / `desktopIntegration.fileAssociations.*` は導入せず、単一の `fileAssociations.{enable,handlers,linux.mime,autoDefaults}` に関連付けポリシーを集約する。`handlers` を目的ベースの主 API とし、OS 差異吸収・Provider 要求・複数形式の一括設定に価値がある抽象化を提供する。`linux.mime` は任意 MIME 型・Desktop ID・順序付き候補の追加・部分上書き用 Escape Hatch とする（具体的な型・命名は実装開始時に固定）。Linux adapter はそれらを一つの `xdg.mimeApps.defaultApplications` に合成して渡し、固定版 Home Manager のワイルドカード展開・具体 MIME 優先・リスト順序保持をそのまま使う。Media と desktopIntegration は利用者向け既定ポリシーを `xdg.mimeApps` へ直接書かない。旧 API と管理対象 Host の利用者向け直接指定は新 API へ移行し、旧合成結果を再現する機構や独自競合解決器は導入しない。ただし個別 Program の非競合な専用スキーム等と Home Manager の `defaultApplicationPackages` は下記の境界で共存する。
- **依存は一方向の事実参照＋個別 Program 要求とする。** Media は mpv / Krita 等、desktopIntegration は Browser 選択を提供する。fileAssociations は Program の最終状態と実効 Browser 選択を**読み取り**、他 Feature 全体を有効化しない。GUI Profile は fileAssociations の有効化を `lib.mkDefault true` で構成し、Media / desktopIntegration は暗黙に要求しない。Host が OFF にした場合は fileAssociations 自身の寄与だけ停止する。独立した各 Feature と GUI Profile の組み合わせを評価し、Media 単独で他 Feature が有効にならないことを確認する。明示 `handlers.video = "mpv"` 等は個別 Program Provider を `lib.mkDefault true` で要求して最終提供状態と OS ごとの Provider 契約を検証し、明示 OFF に負ければ理由付きエラー。**明示ハンドラー → 個別 Program 要求 → Program の最終状態 → 自動既定**の順に評価する。自動既定から Program 要求への逆参照を作らず、要求元による区別は設けない。media / desktopIntegration / fileAssociations の `enable` や `programs.mpv.enable` の相互参照による循環を検出する独立評価テストを追加する。
- **mpv の最終状態による自動既定を表形式の Fixture で固定する。** Linux GUI、fileAssociations / 自動既定 ON、他の明示 MIME・競合候補なしを共通前提とする。`media.mpv.enable = false` + `handlers.video = "mpv"` では mpv Program が最終 ON かつ package 非 null なら動画は明示、音声・画像は自動 mpv。独立 Program ON でも3カテゴリとも自動 mpv。最終 OFF / `package = null` なら3カテゴリの自動既定なし、明示要求は理由付きエラー。明示要求からの波及は意図した動作とし、`autoDefaults.enable = false` と明示 video の併用で動画だけを寄与する。Provider は OS ごとの提供契約を公開し、標準パッケージ・スクリプト付きラッパー・明示カスタムパッケージ・overlay を取得経路で区別しない。IFD 禁止の評価で、標準・契約を満たす明示カスタム・overlay による差し替えで同じ自動既定が生成され、null では生成されないことを確認する。管理対象標準構成の最終パッケージはビルド時に `bin/mpv` と `mpv.desktop` の存在を検証する。`mpv.desktop` を欠く CLI 専用差し替えは Program の提供契約外とし、専用停止 API・自動判定・救済を追加しない。fileAssociations OFF / autoDefaults OFF でも画像の Added Associations が残り得るため、OFF のみで CLI 専用構成を正式対応するとは約束しない。契約外の差し替えは変更者が管理する。任意の差し替えの提供物を自動検出するテスト・由来追跡・評価時 pathExists / IFD・公開宣言 API は設けない。Web Playback の URL 到達は契約を満たす最終パッケージ（録画用 Fixture も必要な Desktop Entry を提供）で検証する。CLI 専用差し替えの候補除去を必須受入条件にしない。Darwin の自動既定・明示選択の対応範囲は Phase 4 で検証する。 Linux の動画・音声は標準 mpv.desktop の宣言、画像は Program の確認済み追加登録型（最低 PNG / JPEG）に限定し、明示・自動とも同じ対応型集合を使う。mpv Program が Home Manager の `xdg.mimeApps.associations.added` を利用し、fileAssociations は既定値を所有する。Program の対応登録は既定ポリシー OFF でも維持し、外部寄与を削除しない。生成 Added Associations / Default Applications と GIO の既定・登録照会を検査し、実際の PNG / JPEG ファイルが GUI 経由で最終 mpv に渡って表示されることを確認する。動画・音声も登録型の代表例で確認する。未確認 MIME 全体のワイルドカードを自動既定にしない。
- **Feature 内部の合成を検証する。** 自動既定 → 明示 `handlers` → `linux.mime` の順で規則を同一入力キー単位に置換・補完してから、一つの設定寄与として Home Manager に渡す。公開 API 経由で `handlers.browser = "glide"` と `linux.mime."text/html" = [ "reader.desktop" "fallback.desktop" ]` を併用し、HTML は reader → fallback のみ、XHTML・HTTP・HTTPS は Glide になることを確認する（外部の独立寄与がない Fixture）。定義順依存の連結を行わない。旧 MIME マップの全置換と旧候補順の完全一致は受入条件とせず、旧明示設定の移行先と変更点を記録する。
- **設定の合成は Nix / Home Manager の既存の意味論に委譲する。** Feature が意図した入力キー・候補リストを渡すことを検証し、同一入力キーの定義合成は Nix、ワイルドカード展開と具体 MIME の適用は Home Manager に任せる。固定版の委譲確認として `video/* = lib.mkForce "chosen.desktop"` と外部 Program の `video/mp4 = lib.mkDefault "external.desktop"` を併用し、生成結果の WebM が `chosen.desktop`、MP4 が `external.desktop` になることを確認する。`text/*` と `text/html` の例も既存の意味論を利用する。`handlers.browser` の変更時は Browser 4種への設定寄与を検証する。展開後の MIME に dotfiles 独自の優先順位を設けない。
- **Home Manager と Program の独立寄与の共存を検証する。** 管理対象 Host の利用者向け直接指定は新 API に移行する。一方、Program の `.desktop` による対応形式登録、Radicle 等の専用スキームの非競合な既定寄与、および `xdg.mimeApps.defaultApplicationPackages` は許容する。`text/html = "chosen.desktop"` と、HTML・PDF を扱うテストパッケージを併用し、生成 `mimeapps.list` が `text/html=chosen.desktop;from-package.desktop`、`application/pdf=from-package.desktop` になることを検査する。複数の package 候補がある場合も固定版 Home Manager の末尾追加順を維持する。外部 Program の既定規則との合成は Nix / Home Manager の既存の意味論に従う。無関係な専用スキームは維持し、fileAssociations OFF / autoDefaults OFF でも外部の独立寄与を消さない。Radicle ON + fileAssociations OFF で `x-scheme-handler/rad` の設定値が残ることを確認し、他の出力要求なしでは `mimeapps.list` が生成されないケースと、Host または外部 Consumer が `xdg.mimeApps.enable = true` を要求して生成されるケースを比較する。fileAssociations OFF は共有基盤を強制 OFF にしない。
- **Emacs 単独 Home の回帰テストを通常の Home 入口から追加する。** Media / desktopIntegration OFF、Emacs Program ON、fileAssociations の独立有効化あり・なしを評価する。`orgProtocol.enable` の既定値が true でも `org-protocol.desktop` が未生成なら `x-scheme-handler/org-protocol` を自動出力しない。Emacs サービスだけ、client だけ、両方 ON を比較し、`text/plain` の自動関連付けはサービスと client の双方が成立し `emacsclient.desktop` が実在し、Server 接続・起動経路が提供される場合だけ生成する。desktopIntegration / orgProtocol 有効時の正のケースも保持し、モジュール import と全 assertion、生成ハンドラーの実在を確認する。 Linux の明示 `handlers.textEditor = "emacs"` は `text/plain = emacsclient.desktop` を提供する。`autoDefaults.enable = false` でも明示規則だけが生成されること、必要な Program・サービス・client の提供を要求し、Host が無効にして契約を満たせない場合は理由付きエラーとなることを検証する。 Linux Org Protocol は既存の Emacs Server / socket activation を使用する。Server 未起動・socket 待受中に生成 Desktop Entry のコマンドでテスト URL を渡し、Server が起動して Org Protocol handler に届くことを確認する。Server 接続・起動経路なしでは既定 OFF、明示 ON は理由付きエラー。新規 Server 起動機構を追加しない。 Org Protocol と textEditor は同じ内部 Server 提供条件を参照する。サービス・client ON でも socketActivation.enable=false / startWithUserSession=false の新規セッションでは自動 textEditor なし、明示要求は理由付きエラー。Server 未起動・socket 待受中に実ファイルを開き、Emacs のバッファに対象ファイルが到達することを確認する。ユーザーセッション起動による提供も確認する。
- **Yazi の互換性変更を明記する。** 現行の `desktop-integration-mime` は Yazi 無効でも `inode/directory` と `text/uri-list` を `yazi.desktop` に設定する。新構成では未提供 Yazi の**自動既定**を生成しないことを意図的な変更として扱い、明示 `handlers.directory = "yazi"` は Yazi Program を要求する。旧 Host の directory / URI 規則が変わるケースをテストし、移行案内に記す。 **Provider の有効化契約も修正する。** 現在の `nix/modules/home/programs/yazi/default.nix` は `programs.yazi.enable = true` を通常優先度で設定するため、Host の `false` と Nix の定義衝突になる。Consumer の明示要求を個別 Provider が満たせるよう、Provider 側の有効化要求を適切な既定優先度（例: `lib.mkDefault true`）にする。GUI 端末起動経路を備えた Fixture で `handlers.directory = "yazi"` のみで Yazi が実効提供され、Host が `programs.yazi.enable = false` を明示したときは強制上書きも同優先度の定義衝突も起こさず、fileAssociations の理由付き assertion に到達することを検証する。Provider の独自設定の無効化、その他の独立 Consumer の要求についても実効状態を検査する。 Terminal Feature は GUI Linux で選択 Provider の Desktop ID を upstream `xdg.terminal-exec` に渡す。Kitty・Alacritty・WezTerm の Desktop Entry と子コマンド起動を検証する。Yazi の自動既定は実効 GUI 端末経路がある場合のみ、明示 directory は経路不成立なら理由付きエラー（Terminal Feature を暗黙に起動しない）。GIO で inode/directory の既定・登録を照会し、実際にディレクトリを開いて選択端末上の Yazi に対象パスが渡ることを確認する。現行環境 HEAD b8f70fb でも `gio open $HOME` の端末探索失敗が再現された。Yazi 専用ラッパーは新設せず、TTY への GUI 基盤の無条件導入は避ける。 `programs.yazi.enable = true` / `programs.yazi.package = null` と `xdg.terminal-exec.enable = true` / `xdg.terminal-exec.package = null` をそれぞれ単独・両方の負の Fixture で検証する。外部から実体を提供しない条件で、設定ファイルのみ生成されても提供済みとみなさず、directory 自動既定なし、明示 `handlers.directory = "yazi"` は理由付きエラーとなることを確認する。Yazi の finalPackage は package 非 null の場合にのみ参照し、型エラー等で理由付き assertion が隠れないことも確認する。非 null のカスタムパッケージは提供契約を信頼し、外部実体の自動探索は行わない。
- Phase 2 の新 FileChooser API とラッパー・Portal の受入テストは維持する。旧 backend API からの二段階切替や互換動作のテストは設けない。
- Linux の Web Playback adapter を Browser 別に構成する。既定値は選択 Browser・対応 adapter・実効 mpv の成立に従う。Media 単独で Browser 未選択なら既定 OFF、明示 ON なら不足依存を示すエラーとし、他 Feature / Browser を暗黙に有効化しない。Browser あり＋mpv 不在 → 既定 OFF、同条件で明示 ON → エラー、独立 mpv 提供 → 既定 ON を検証する。録画用 `finalPackage` への URL 到達と、OFF／Browser 切替後の Media 由来設定が消えることを確認する。**Firefox の新規プロファイルで ff2mpv が自動的に有効化され、ブラウザー操作から URL を送れること**を受入条件とし、native host 直接呼び出しだけで済ませない。**Qutebrowser を選択した場合は `,m` から現在の URL が `programs.mpv.finalPackage` に届くこと**もテストする。
- 固定版 Home Manager の `xdg.mimeApps.defaultApplications` を生成する adapter のテストでは、入力規則、upstream の `video/*` 展開と具体 MIME の適用、新 API の候補順を確認する。競合するシステム MIME 規則がある場合の実効値は OS / XDG 実装への適用確認として検証し、dotfiles 独自の解決規則は設けない。実効 Program と `mpv.desktop` の存在は別々に検証し、利用者向け既定規則は `fileAssociations` が所有し、生成ファイルは Home Manager が管理して外部の非競合規則と追加候補も保持する。
- TTY Profile は GUI 固有の Feature を要求しない。GUI Profile なしの Media-only Home（Terminal OFF を含む）では他 Feature・Browser・Portal・FileChooser を暗黙に有効化しない。GUI Profile または Host が組み合わせを明示した場合の Web Playback / fileAssociations と、Browser 明示 `null` 時の無寄与を検証する。 GUI Profile の `desktopIntegration.enable = false` 上書きで `browser.selected = "glide"` が残り、独立 Glide Program が有効でも、実効 Browser 選択なし、Web Playback 自動 OFF、HTML/XHTML/HTTP/HTTPS の Browser 選択由来自動寄与なし、独立 Glide と fileAssociations の明示 Browser handler は維持することを検証する。
- Phase 2 の Portal テストを再利用する。管理対象の指定先への設定生成、`auto` の無寄与、明示 `terminal` / `system` の必要な Provider と適切な環境での動作を確認する。共通・セッション固有ファイル間の自動合成や外部設定との実効優先順位を保証する独自テストは追加しない。
- `media.firefoxIntegration` の Linux 旧設定を移行し、Darwin では既存の経路を維持する。

## Phase 4 — Darwin adapters と旧経路撤去

**対象:** `desktop-integration.nix`、`desktop-integration/org-protocol.nix`、独立 `file-associations/` の Darwin adapter、FileChooser の内部 adapter、`nix/modules/home/programs/emacs/darwin-app.nix`、GUI Profile、`media.nix`、Browser Program、Darwin Home テスト、`nix/ci/default.nix`。

- Darwin GUI Profile にも Media・desktopIntegration・fileAssociations の個別有効化と Browser = Glide の既定選択を適用する。Web Playback は必要な依存が揃う場合に既定 ON とする。Browser 提供は新 Provider、URL 転送は最終 mpv、ファイル選択は利用可能な macOS 標準機構を利用する。 Darwin の fileChooser.mode=auto は OS・アプリ標準動作への委譲として無寄与で成立し、terminal は理由付き未対応エラーになることを評価する。全アプリへのネイティブダイアログ強制を受入条件にしない。
- XDG Portal・XDG MIME・termfilechooser を Darwin の共通機能として起動しない。`orgProtocol.enable` は Darwin の対応実装ができるまで既定 OFF、明示 ON は理由付きエラーとし、XDG Desktop Entry を生成しない。**独立 fileAssociations Feature の Darwin adapter が、今回新設する Launch Services の既定アプリ設定担当**であり、UTI / Bundle ID の解決と `duti` 等による適用を一つの activation 経路にまとめる。現行 `nix/modules/home/programs/emacs/darwin-app.nix` の `registerEmacsApp` は `.app` 登録だけに限定し、`public.plain-text` / `public.source-code` / `public.shell-script` への `duti -s` 書き込みを adapter の有効化と同時に移す。Emacs Program 単独では fileAssociations を要求せず、既定アプリを設定しない（意図的な動作変更）。新規 macOS ユーザーで fileAssociations 未指定 / OFF の場合に旧3種の既定設定を行わないことを確認する。Darwin の公開 `fileAssociations.handlers.textEditor` は旧3種の UTI を一括設定する。実 Provider は `emacs` とし、Host の `fileAssociations = { enable = true; handlers.textEditor = "emacs"; };` で3種への適用を確認する。Neovim は将来の交換候補とするが、Neovide 等の GUI / 端末起動やファイル受け渡しの実装は今回の範囲外であり、本番の対応済み選択肢には加えない。別の Bundle ID を提供するテスト専用 Provider を Fixture 内で選択肢に追加し、同じ公開 API `fileAssociations.handlers.textEditor = "test-editor";` を経由して Emacs ON・別エディター選択・再 activation を検証する。内部 UTI マップの直接上書きだけで済ませない。macOS 実機ではファイルを受け取れる登録済みのテストアプリを使い、**旧3種それぞれの Launch Services 実効ハンドラーが別エディターの Bundle ID のまま**であり、処理順で Emacs に戻らないことを照会する。テスト専用 Provider は本番の選択肢に混ぜない。対応済み Browser を切り替えた場合も HTML / XHTML の文書型と HTTP / HTTPS の URL スキームの実効ハンドラーを**それぞれ**検証し、OS が同意を要求する場合は利用者が承認することを正常系の前提とし、変更要求と承認後の実効値確認を区別する。Browser・Emacs・mpv 等に共通の契約とし、未承認・拒否を成功扱いせず、独自の同意状態管理や再試行機構は導入しない。Linux の Home Manager MIME と Darwin の UTI API を混同しない。 activation DAG に配置・登録・既定設定の依存順を明示する。管理対象 Home は `copyApps` → `registerEmacsApp` → 既定設定とし、他の選択 Provider に必要な登録も完了してから適用する。生成 activation の順序を検査し、新規ユーザーの初回 activation で `handlers.textEditor = "emacs"` を選択して設定を要求し、OS の同意が必要なら承認後に3種の UTI を実効照会する。再 activation のみで初回登録の保証を代替しない。
- **Darwin mpv の関連付け契約を検証する。** 固定版標準 `mpv.app` の動画・音声登録情報と Bundle ID をビルド時に確認する。GUI / 自動既定 ON では `public.movie` / `public.video` と `public.audio` に mpv を適用し、画像は寄与しない。初回の設定要求を確認し、必要な OS 同意の承認後に実効ハンドラーを照会し、明示 `handlers.video = "mpv"` / `handlers.audio = "mpv"` も自動既定 OFF で適用されること、`handlers.image = "mpv"` は理由付き未対応エラーとなることを確認する。画像関連付けのための Info.plist 補完は行わず、Program 提供・Web Playback は独立して検証する。カスタム・overlay の提供契約は Linux と同じ責務境界を適用する。
- **既存ホストとは独立した Darwin Qutebrowser 選択テスト**を追加する。`browser.selected = "qutebrowser"` かつ Web Playback ON とし、生成された `,m` が PATH 上の `mpv` ではなく **`programs.mpv.finalPackage` の実行ファイル**へ URL を渡すことを検査する。Linux の Phase 3 と Darwin の Phase 4 の双方で `,m` 契約を検証する。Program 提供・起動、Web Playback、既定 Browser 関連付けの対応可否は独立に扱う。Darwin Qutebrowser の既定 Browser 関連付けは今回の対象外とし、選択 Browser が Qutebrowser の場合に自動既定から除外されること、`fileAssociations.handlers.browser = "qutebrowser"` の明示要求が理由付きエラーになること、関連付け OFF または別の対応済み Provider の明示選択では Qutebrowser の提供・Web Playback を妨げないことを確認する。固定版 Nixpkgs の `.app` の対応文書型・URL スキーム情報不足の修正は要求しない。将来は upstream 修正を優先し、暫定修正が必要なら Program の package override で扱う。fileAssociations 内でパッケージを修正しない。Darwin Qutebrowser の初回登録・4種の実効照会・OS からの HTTPS URL 受け取りは将来の関連付け対応時の検証とする。
- **Darwin の2ホスト×2テーマ＝4 Home 構成**で `Glide.app`、使用プロファイルの ff2mpv 拡張、manifest の `allowed_extensions` と拡張 ID の一致、Glide 連携から `programs.mpv.finalPackage` への URL 到達を新契約として検証し、Darwin の切替と同時に `media.programs`・`media.firefoxIntegration` の旧経路を撤去する。通常 PR CI の代表 Home 1件だけでは承認しない。
- 旧 MIME / FileChooser / Emacs 既定アプリの移行先と意図的な動作変更を記録する。旧副作用・候補合成の完全再現は要求しない。

### Phase 4 必須の Darwin Home ビルド

CI の通常 PR と全体ビルドの `nix/ci/default.nix` にある `macos-14` を `macos-latest` に移行し、生成済みワークフローを再生成する。2026-11-25 時点の GitHub 公式 runner 一覧では arm64。実ジョブのアーキテクチャが aarch64-darwin に合うことを確認する。runner image の更新は許容し、Nix inputs の固定とは区別する。廃止済み runner の修正は着手前に独立実施可能。通常 PR CI の代表ビルドとは別に、次の4件を **macOS runner 上で全件**実行する（移行 PR の必須チェックに追加）。

```sh
nix build --no-update-lock-file \
  '.#checks.aarch64-darwin.build-home-aarch64-darwin-a--account-a--theme-light' \
  '.#checks.aarch64-darwin.build-home-aarch64-darwin-a--account-a--theme-dark' \
  '.#checks.aarch64-darwin.build-home-aarch64-darwin-hiromichisugiura--account-hiromichisugiura--theme-light' \
  '.#checks.aarch64-darwin.build-home-aarch64-darwin-hiromichisugiura--account-hiromichisugiura--theme-dark'
```

ビルドに加え、各 Home の生成物について Glide の拡張・native host 対応・最終 mpv への URL 引き渡しを検査する。Darwin 実機での GUI 操作確認は別途行う。
