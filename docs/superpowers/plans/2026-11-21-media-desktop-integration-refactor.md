# Media / desktopIntegration / fileAssociations リファクタリング実装計画

**前提:** [設計仕様](../specs/2026-11-21-media-desktop-integration-design.md)

## Phase 1 — mpv の独立化

**対象:** `nix/modules/home/programs/mpv/default.nix`（新規）、`nix/modules/home/features/media.nix`。

- `media.mpv.settings` を Program に移し、`autofit-large` を `autofit-larger` に修正する。旧オプションは移行先を示すエラーにする。
- `programs.mpv.finalPackage` を実効実行ファイルとして扱い、`scripts` や package 上書きも反映する。
- 生成 `mpv.conf` の読み込み結果について、終了コードだけでなく `Error parsing option` を検査する。単独利用と `package = null` も確認する。

## Phase 2 — Browser 選択・提供

**対象:** `nix/modules/home/features/desktop-integration/`、`nix/modules/nixos/features/desktop-integration.nix`、`nix/profiles/variants/desktop-integration/{home,nixos}.nix`、`nix/modules/home/features/session-gui.nix`、`nix/modules/home/programs/{glide,firefox,qutebrowser,krita}/`、`nix/modules/home/programs/niri/`、GUI Profile、`media.nix`、`nix/tests/{home,nixos,system}/desktop-integration.nix`、`nix/tests/home/desktop-integration-wrapper.nix`。

- **旧経路の撤去前に**、FileChooser の未指定時既定を **セッション／OS 既定への委譲**に変更する。旧 `portal.fileChooser.backend` が未指定なら FileChooser の backend・追加パッケージ・ラッパー・強制設定を寄与しない。従来の未指定既定 `termfilechooser` からの意図的変更として明示する。**Terminal が有効なだけでは termfilechooser を選ばない。** Host が指定済みの `"gtk"` / `"termfilechooser"` / `null` は従来どおり優先し、Terminal ON + 明示 GTK は GTK、明示 `null` は無寄与と検証する。明示 backend の適用先が実効セッション／明示 `portal.configName` から特定できない場合は理由付きエラーを出し、共通ファイルだけで保証したことにしない。**GUI Profile なし・Media-only・Terminal OFF** の Home で desktopIntegration が自動 ON、Glide が実効提供され、Terminal 不在に起因する評価失敗や FileChooser 強制設定がないことを確認する（GTK の選択は要求しない）。**このテストを満たす同じ変更で** Browser Provider と `desktopIntegration.browser.selected` を導入し、Linux GUI 既定を `lib.mkDefault "glide"` に移す。Media 旧 Browser 提供の撤去を先行しない。同じ変更で Krita を `media.graphics.krita.enable` に移し、Linux GUI で提供、TTY では要求なしを確認する。
- **Portal Service の所有者を Home と NixOS の双方で分離する。** `auto` で backend も外部 `extraPortals` もない場合、独立 Home **および独立 NixOS** のどちらでも desktopIntegration は `xdg.portal.enable = true` + `extraPortals = []` を生成しない。Portal の起動は NixOS／セッション／明示 Home の管理に委ね、**欠けたパッケージを追加してごまかさず**、最終の Home Manager と NixOS の全 assertion がそれぞれ成立することを受入条件とする。登録済み `desktop-integration-nixos` テストに **Niri OFF・外部 backend なし・FileChooser backend 未指定**を追加し、既存の「既定 termfilechooser」期待値を新 `auto` に更新する。独立 Home の Media-only / Terminal OFF ケースも維持する。Host や他 Feature が Portal を有効にしている場合は保持する。TTY は Media／Terminal 単独で Portal・FileChooser・termfilechooser を要求しない。
- **NixOS／Home の切替を同じ Phase で整合させる。** 管理対象 Linux GUI が委譲型 `auto` へ移るなら、NixOS 側の暗黙の `portal.fileChooser.backend = "termfilechooser"` と `mkForce` を同時に撤去する。端末 chooser を維持するホストでは Home のラッパーと NixOS の backend を**明示的な要求として**維持する。**NixOS 単体で明示 terminal（Phase 2 は旧 `portal.fileChooser.backend = "termfilechooser"`）を指定した場合の合格条件は、backend の導入とシステム側 Portal の実効選択まで**とし、端末・Yazi ラッパーやファイル選択完了は要求しない。**NixOS + 内包 Home** では、実効 FileChooser の選択、backend パッケージ、端末・Yazi ラッパーの有無を整合させ、GUI アプリからの実際のファイル選択完了までを確認する。独立 NixOS と統合 Home の評価を別の受入ケースに分ける。
- **Portal Policy Composition を Service 有効化から分離する。** NixOS が Portal 本体を管理して Home の `xdg.portal.enable` が false でも、Home の明示 `portal.secretBackend = "none"` 等から **実際の `xdg.configFile."xdg-desktop-portal/niri-portals.conf"`** を生成・配置する経路を Phase 2 で導入する。Home Manager の `xdg.portal.config` が残るだけでは不合格。Home が `xdg.portal.enable = true` の構成では従来の生成経路と重複させず、同一パスの単一所有と Host の明示ポリシーの合成を保証する。隔離 D-Bus の **NixOS（`Secret=gnome-keyring`）+ 内包 Home（`Secret=none`、chooser `auto`）** 統合テストで、ユーザー側 `niri-portals.conf` の生成物と実効 `Secret=none` の両方を確認する。FileChooser が `auto` でも非 FileChooser ポリシーを無視せず、既存の `Inhibit=none` 等に回帰がないことを確認する。
- **Phase 2 で共通ポリシーが既存セッション固有設定に隠れる回帰も検証する。** `portal.configName = "common"`、chooser `auto`（Phase 2 は backend 未指定）、ユーザー側 `portals.conf` の `Secret=none`、システム側 `Secret=gnome-keyring` の Fixture を作る。共通ファイルだけなら実効 `none`、同じユーザー側ディレクトリに管理下の `niri-portals.conf`（`Access=gtk` のみ）がある場合も、明示 `Secret=none` を固有ファイルへ合成して実効 `none` を維持する。`Access=gtk`、非関連ポリシー、共通設定の他セッション向け出力を保持し、FileChooser の強制選択は追加しない。管理外の固有ファイルがある場合は上書きせず競合を報告する。宣言的な所有権競合は評価時、実ホームにだけ存在する管理外ファイルは activation の事前検査で確認し、隔離 D-Bus で Secret の実効値を照会する。
- **セッション識別と設定管理を分離する。** 有効な `sessionGui` は Niri 等の設定を管理し、別の内部実効値 `desktopSession.id = niri | sway | null` がセッション識別を提供する。Sway の識別だけで設定・起動管理を強制しない。`sessionGui.enable = false` なら `sessionGui.session` の既定 `niri` を利用せず、Host 明示セッション／既存 `portal.configName = "sway"` を必要なときに解決する。有効な `sessionGui.session = "niri"` と明示 `portal.configName = "sway"` は競合エラー＋移行案内とする。Niri・Sway・不明・独立 Home の各評価テストを追加する。Session Provider は適用先を、FileChooser Provider は実装を、Portal Composition は Host 明示ポリシーとの合成を担当する。
- Niri の固定 Glide 起動を選択 Provider のコマンドに置き換える。desktopIntegration OFF、選択 `null`、Niri 単独で起動行がないことを確認し、**肯定ケースとして `browser.selected = "qutebrowser"` を追加**する。生成 `config.kdl` の `spawn-at-startup` が選択 Provider の最終実行ファイルを参照し、Qutebrowser の起動行が**正確に1回**、Glide の固定起動行が**0回**であることを確認する。単純な `glide` 行の有効化条件付けだけではテストを通さない。
- Glide の `mkDefault` は GUI Profile または Media の GUI 要求があるときだけ適用する。**GUI Profile なし・Media OFF の desktopIntegration 単独**で、Browser がない場合は `selected = null` かつ Browser 関連付けなしを検証する。現行の **Qutebrowser のみ有効な Home** は `browser.selected = "qutebrowser"`、**Glide のみ**または **Glide + Qutebrowser** が有効な Home は `browser.selected = "glide"` へ移行する。いずれも HTML・XHTML・HTTP・HTTPS の4件が従来の Browser を指すことを検証する。旧 Program フラグを Browser 選択 API と同一視せず、必要な Host の明示設定を更新する。
- Phase 2 は旧提供経路を移行途中として維持し、Linux では新 Browser Provider から Browser 4関連付けを生成する。Phase 3 の独立 `fileAssociations` への切替までは **旧 `mimeApps.defaultApplications` の全置換 semantics を変更しない**。**desktopIntegration 単独**で `inode/directory` だけを指定した場合は、同 Feature の関連付け寄与が1件であることを検証する。**Media 併用**ではそのディレクトリ設定と Media の `video/mp4` 等の関連付けがともに最終 `mimeapps.list` に残ることを確認する（展開後の総件数は固定しない）。新 API の部分上書きは別途検証する。
- 既存の **`desktop-integration-wrapper` チェックも Phase 2 で移行**する。`nix/tests/home/desktop-integration-wrapper.nix` の Fixture に旧 `portal.fileChooser.backend = "termfilechooser"` と対象セッションを明示し、生成されたラッパーから Kitty・Alacritty・WezTerm、Yazi への引数・起動経路を引き続き確認する。未指定 `auto` の Fixture はラッパーなしを別途確認する。
- Darwin の Glide・ff2mpv 旧経路は維持する。Linux で無効になった `media.programs` の明示設定は移行エラーにする。

## Phase 3 — 独立 fileAssociations Feature と Linux adapters

**対象:** `nix/modules/home/features/media.nix`、`nix/modules/home/features/file-associations/`（新規、内部 Linux adapter 含む）、`desktop-integration/{mime-apps,portal,termfilechooser}.nix`、Feature の import / Profile 構成、Browser 共通設定、関連テスト、`nix/modules/home/programs/yazi/default.nix`。

- **`fileAssociations` を独立した公開 Feature として実装する。** `media.fileAssociations.*` / `desktopIntegration.fileAssociations.*` は導入せず、単一の `fileAssociations.{enable,handlers,linux.mime,autoDefaults}` に関連付けポリシーを集約する。`handlers` は動画・音声・画像・Browser・ディレクトリなどの論理 Provider 名、`linux.mime` は任意 MIME 型・Desktop ID・順序付き候補の高度な指定を同一 Feature から行う（具体的な型・命名は実装開始時に固定）。Linux adapter はそれらを一つの `xdg.mimeApps.defaultApplications` に合成して渡し、固定版 Home Manager のワイルドカード展開・具体 MIME 優先・リスト順序保持をそのまま使う。Media と desktopIntegration は利用者向け既定ポリシーを `xdg.mimeApps` へ直接書かない。移行期間の旧 API / Host の Home Manager 直接指定は実効比較と競合検出を行い、最終的には多重公開入口を残さない。ただし個別 Program の非競合な専用スキーム等と Home Manager の `defaultApplicationPackages` は下記の境界で共存する。
- **依存は一方向の事実参照＋個別 Program 要求とする。** Media は mpv / Krita 等、desktopIntegration は Browser 選択を提供する。fileAssociations は両者の有効状態と実効選択を**読み取り**、Media / desktopIntegration 全体を有効化しない。GUI の Media / desktopIntegration は fileAssociations の有効化を `lib.mkDefault true` で提案できるが、Host が OFF にした場合はfileAssociations 自身の関連付けだけを生成せず、外部の独立寄与を妨げない。明示 `handlers.video = "mpv"` 等は個別 Program Provider を `lib.mkDefault true` で要求して最終提供／Desktop Entry を検証し、明示 OFF に負ければ理由付きエラー。**明示ハンドラー → 個別 Program 要求 → Program の最終状態 → 自動既定**の順に評価する。自動既定から Program 要求への逆参照を作らず、要求元による区別は設けない。media / desktopIntegration / fileAssociations の `enable` や `programs.mpv.enable` の相互参照による循環を検出する独立評価テストを追加する。
- **mpv の最終状態による自動既定を表形式の Fixture で固定する。** GUI、fileAssociations / 対象カテゴリの自動既定 ON、他の明示 MIME・競合候補なしを共通前提とする。`media.mpv.enable = false` + `handlers.video = "mpv"` では mpv Program が最終 ON、`video/*` は明示 mpv、`audio/*` と `image/*` は自動 mpv。Media の要求が OFF でも独立 mpv Program ON なら3カテゴリとも自動 mpv。最終 OFF / Desktop Entry 不在なら3カテゴリの mpv 自動既定はなし（明示要求の失敗は理由付きエラー）。明示 video 要求からの波及を意図した動作として扱い、音声・画像の明示選択やカテゴリ別自動既定 OFF は尊重する。
- **旧 MIME の移行は最終生成物の一致で判定する。** Media と desktopIntegration が両方 `video/*` に寄与した旧 Fixture では、`video/webm` の候補 `mpv.desktop;first.desktop;second.desktop` と `video/mp4` の `special.desktop` を、移行後も同じ順序・内容で維持する。単なる旧デスクトップ側 `[ "first.desktop" "second.desktop" ]` のコピーは不合格。Media 側だけで旧マップ全置換した Fixture では、該当カテゴリの `autoDefaults` を抑えて音声・動画の自動既定が復活しないことを確認する。`video/mp4` 以外に音声・画像・ディレクトリ・Browser 4種を比較し、意図的な互換性変更は別に記録する。Host による直接 Home Manager 設定と Feature の新 API が同一設定を二重に所有しないよう移行案内か理由付き競合エラーを出す。
- **優先順位の2段階をテストする。** Nix の同一 MIME キーでは明示 Host / `linux.mime` が自動 `mkDefault` に優先する。異なるキー（`text/*` と `text/html`）では Home Manager がワイルドカードを先に展開して具体 MIME を後適用し、`text/html` が勝つ。`handlers.browser` を明示変更した場合は Browser 4種の最終関連付けを統一して追従させるが、さらに個別 `linux.mime` 指定があればそちらを尊重する。候補順も比較する。
- **Home Manager と Program の独立寄与の共存を検証する。** Host の `xdg.mimeApps.defaultApplications` 直接指定は利用者ポリシーの二重入口として移行・競合検出する。一方、Program の `.desktop` による対応形式登録、Radicle 等の専用スキームの非競合な既定寄与、および `xdg.mimeApps.defaultApplicationPackages` は許容する。`text/html = "chosen.desktop"` と、HTML・PDF を扱うテストパッケージを併用し、生成 `mimeapps.list` が `text/html=chosen.desktop;from-package.desktop`、`application/pdf=from-package.desktop` になることを検査する。複数の package 候補がある場合も固定版 Home Manager の末尾追加順を維持する。fileAssociations が明示選択した実効キーに Program の異なる既定が競合する場合は明示候補順を優先し、両立不能なら出所・キー付きエラーにする。無関係な専用スキームは維持し、fileAssociations OFF / autoDefaults OFF でも外部の独立寄与を消さない。
- **Emacs 単独 Home の回帰テストを通常の Home 入口から追加する。** Media / desktopIntegration OFF、Emacs Program ON、fileAssociations の独立有効化あり・なしを評価する。`orgProtocol.enable` の既定値が true でも `org-protocol.desktop` が未生成なら `x-scheme-handler/org-protocol` を自動出力しない。Emacs サービスだけ、client だけ、両方 ON を比較し、`text/plain` の自動関連付けはサービスと client の双方が成立し `emacsclient.desktop` が実在する場合だけ生成する。desktopIntegration / orgProtocol 有効時の正のケースも保持し、モジュール import と全 assertion、生成ハンドラーの実在を確認する。
- **Yazi の互換性変更を明記する。** 現行の `desktop-integration-mime` は Yazi 無効でも `inode/directory` と `text/uri-list` を `yazi.desktop` に設定する。新構成では未提供 Yazi の**自動既定**を生成しないことを意図的な変更として扱い、明示 `handlers.directory = "yazi"` は Yazi Program を要求する。旧 Host の directory / URI 規則が変わるケースをテストし、移行案内に記す。 **Provider の有効化契約も修正する。** 現在の `nix/modules/home/programs/yazi/default.nix` は `programs.yazi.enable = true` を通常優先度で設定するため、Host の `false` と Nix の定義衝突になる。Consumer の明示要求を個別 Provider が満たせるよう、Provider 側の有効化要求を適切な既定優先度（例: `lib.mkDefault true`）にする。`handlers.directory = "yazi"` のみで Yazi が実効提供され、Host が `programs.yazi.enable = false` を明示したときは強制上書きも同優先度の定義衝突も起こさず、fileAssociations の理由付き assertion に到達することを検証する。Provider の独自設定の無効化、その他の独立 Consumer の要求についても実効状態を検査する。
- `desktopIntegration.fileChooser.{enable,mode}` を追加。**`auto` は backend を選ばず、Portal の FileChooser 指定・パッケージ・ラッパーを追加せず、Session Provider／OS 既定へ委譲**する。Terminal 有無で GTK／termfilechooser を自動強制する案は撤回する。`mode = "terminal"` は Linux の termfilechooser、`mode = "system"` は Linux の GTK（Darwin では OS 標準）を**明示要求**し、Session Provider／明示適用先と Portal Composition で実効動作を保証する。対応できない場合は理由付きエラー。`enable = false` は FileChooser だけ無寄与とし、外部から `FileChooser=gtk` と対応 `xdg-desktop-portal-gtk` を提供した際の実効選択をテストする。旧 `backend = "gtk"` / `"termfilechooser"` / `null` と新 `system` / `terminal` / `enable = false` の移行を明示し、`portal.*` の高度な設定は実装固有として扱う。**Phase 2 のラッパーテストを Phase 3 で `fileChooser.mode = "terminal"` へ切替**し、明示選択テストとして維持する。
- Linux の Web Playback adapter を Browser 別に構成する。既定値は選択 Browser・対応 adapter・実効 mpv の成立に従う。Browser あり＋mpv 不在 → 既定 OFF、同条件で明示 ON → エラー、独立 mpv 提供 → 既定 ON を検証する。録画用 `finalPackage` への URL 到達と、OFF／Browser 切替後の Media 由来設定が消えることを確認する。**Firefox の新規プロファイルで ff2mpv が自動的に有効化され、ブラウザー操作から URL を送れること**を受入条件とし、native host 直接呼び出しだけで済ませない。**Qutebrowser を選択した場合は `,m` から現在の URL が `programs.mpv.finalPackage` に届くこと**もテストする。
- 固定版 Home Manager の `xdg.mimeApps.defaultApplications` を生成する adapter のテストでは、`video/*` 展開、`video/mp4` 明示優先、`video/webm` を含む旧合成後の候補順、競合するシステム MIME 規則があるときの実効値を確認する。論理動画ハンドラーに `video/mp4` が追従するのは個別指定がない場合だけ。実効 Program と `mpv.desktop` の存在は別々に検証し、利用者向け既定規則は `fileAssociations` が所有し、生成ファイルは Home Manager が管理して外部の非競合規則と追加候補も保持する。
- TTY では GUI 固有の fileAssociations 自動既定・Portal・FileChooser を既定 OFF にし、従来のホストテストを更新する。**Terminal OFF の `auto` は成功するが GTK の選択までは保証しない**。`auto` は Terminal ON/OFF いずれも chooser の強制設定・専用ラッパーを寄与しない。明示 `terminal` で Terminal 不在ならエラー。Phase 2 の **GUI Profile なし・Terminal OFF の Media-only GUI Home** の Glide／desktopIntegration／無強制テストを維持し、Web Playback の実効提供と Browser 明示 `null` 時の無寄与も確認する。
- Portal の受入テストは **`auto` の FileChooser 無寄与**と **明示選択の実効保証**を分離する。`auto` 中でも Host が明示した `Secret` / `Access` 等のポリシーはユーザー設定へ出力し、ファイル生成と実効値まで検証する。`auto` では Niri・Sway・セッション不明の FileChooser 選択を変更せず、セッション／OS 既定に委譲する。非 FileChooser の明示ポリシーは Phase 2 の共通ファイル隠蔽テストを引き継ぎ、管理下の固有ファイルへ必要に応じて合成する。明示 `terminal` / `system` では、対象 Niri / Sway 固有設定にそれぞれ `termfilechooser` / `gtk` を反映する。ユーザー側 `sway-portals.conf` が既存 GTK を指定していても明示 terminal の実効値が termfilechooser になること、明示 system も逆方向に勝つことを隔離 D-Bus セッションで確認する。対象セッション不明で共通 `portals.conf` のみでは保証できない場合、**terminal・system 両方**を理由付きエラーとする。新設したユーザー側 `sway-portals.conf` のため共通 `Access=none` / `secretBackend` が消えないよう明示ポリシーを合成する。さらに**システム側とユーザー側の設定を別ディレクトリ**に配置した隔離 D-Bus テストで、システム側 `sway-portals.conf` の `Inhibit=none` が、ユーザー側で chooser を `gtk` / `termfilechooser` に切り替えた後も**実効 `none` のまま**であることを確認する。単に FileChooser / Access だけが通るテストや、ユーザー側に `default=gnome;gtk` を無条件に書く実装では合格としない。共通設定は他セッション向けに維持する。管理対象外の競合は検出する。Phase 2 で追加した `portal.configName = "common"` + 既存固有ファイルの回帰テストを新 API でも維持し、有効な `sessionGui.session = "niri"` と明示 `portal.configName = "sway"` の衝突は理由付き移行エラーとする。
- `media.firefoxIntegration` の Linux 旧設定を移行し、Darwin では既存の経路を維持する。

## Phase 4 — Darwin adapters と旧経路撤去

**対象:** `desktop-integration.nix`、`desktop-integration/org-protocol.nix`、独立 `file-associations/` の Darwin adapter、FileChooser の内部 adapter、`nix/modules/home/programs/emacs/darwin-app.nix`、GUI Profile、`media.nix`、Browser Program、Darwin Home テスト、`nix/ci/default.nix`。

- Darwin GUI にも Browser = Glide、Web Playback = ON の機能的な既定動作を適用する。Browser 提供は新 Provider、URL 転送は最終 mpv、ファイル選択は利用可能な macOS 標準機構を利用する。
- XDG Portal・XDG MIME・termfilechooser を Darwin の共通機能として起動しない。`orgProtocol.enable` は Darwin の対応実装ができるまで既定 OFF、明示 ON は理由付きエラーとし、XDG Desktop Entry を生成しない。**独立 fileAssociations Feature の Darwin adapter が、今回新設する Launch Services の既定アプリ設定担当**であり、UTI / Bundle ID の解決と `duti` 等による適用を一つの activation 経路にまとめる。現行 `nix/modules/home/programs/emacs/darwin-app.nix` の `registerEmacsApp` は `.app` 登録だけに限定し、`public.plain-text` / `public.source-code` / `public.shell-script` への `duti -s` 書き込みを adapter の有効化と同時に移す（旧 Emacs 既定の互換性も明示的に移行）。Emacs 有効・別エディターを既定選択・再 activation というケースで、**Launch Services の実効ハンドラーが別エディターの Bundle ID のまま**であり、処理順で Emacs に戻らないことを macOS 上で照会する。Browser を切り替えた場合も HTML / XHTML の文書型と HTTP / HTTPS の URL スキームの実効ハンドラーを**それぞれ**検証し、OS 同意待ち／拒否／適用成功を区別して完了判定する。Linux の Home Manager MIME と Darwin の UTI API を混同しない。
- **既存ホストとは独立した Darwin Qutebrowser 選択テスト**を追加する。`browser.selected = "qutebrowser"` かつ Web Playback ON とし、生成された `,m` が PATH 上の `mpv` ではなく **`programs.mpv.finalPackage` の実行ファイル**へ URL を渡すことを検査する。選択した Browser の Darwin Provider が未対応なら契約エラーとし、対応実装なしに成功とみなさない。Linux の Phase 3 と Darwin の Phase 4 の双方で `,m` 契約を検証する。
- **Darwin の2ホスト×2テーマ＝4 Home 構成**で `Glide.app`、使用プロファイルの ff2mpv 拡張、manifest の `allowed_extensions` と拡張 ID の一致、Glide 連携から `programs.mpv.finalPackage` への URL 到達を検証してから、`media.programs`・`media.firefoxIntegration` の旧経路を同時撤去する。通常 PR CI の代表 Home 1件だけでは承認しない。
- 旧 `mimeApps`／FileChooser backend の明示設定は、独立 `fileAssociations.handlers` / `linux.mime` / `autoDefaults` への移行先、または理由付き移行エラーで扱う。既存 Home Manager の詳細 MIME の表現力は**内部変換で利用**しつつ、公開設定の所有者を分散させない。従来の候補順・個別 MIME 上書き・Emacs の Darwin 既定アプリの副作用を黙って変更しない。

### Phase 4 必須の Darwin Home ビルド

通常 PR CI の代表ビルドとは別に、次の4件を **macOS runner 上で全件**実行する（移行 PR の必須チェックに追加）。

```sh
nix build --no-update-lock-file \
  '.#checks.aarch64-darwin.build-home-aarch64-darwin-a--account-a--theme-light' \
  '.#checks.aarch64-darwin.build-home-aarch64-darwin-a--account-a--theme-dark' \
  '.#checks.aarch64-darwin.build-home-aarch64-darwin-hiromichisugiura--account-hiromichisugiura--theme-light' \
  '.#checks.aarch64-darwin.build-home-aarch64-darwin-hiromichisugiura--account-hiromichisugiura--theme-dark'
```

ビルドに加え、各 Home の生成物について Glide の拡張・native host 対応・最終 mpv への URL 引き渡しを検査する。Darwin 実機での GUI 操作確認は別途行う。
