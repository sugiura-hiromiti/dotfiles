# OSK 自動表示・非表示

日付: 2026-11-04
状態: 実装済み（GUI での実機確認は未実施）

## 目的と動作

特定のホストで選択できる、ホストに依存しない共通 OSK 機能を提供する。
入力欄にフォーカスすると表示し、フォーカスが外れると非表示にする。
ホスト名、機種名、内蔵画面名を機能の実装条件に含めない。

## 方式

既存の wvkbd と fcitx-virtualkeyboard-adapter を使う方式を推奨する。
Fcitx が検知したフォーカスの変化を、wvkbd の明示的な表示・非表示に接続する。
既存の入力メソッドとキーボードを継続して利用できるため、変更範囲が小さい。
アダプタの既存バージョンは入力メソッドの有効・無効を監視しているため、
共通モジュール内で監視イベントを `InputContextFocusIn` / `InputContextFocusOut` に変更する。

代替の wvkbd `--auto` は compositor の input-method-v2 対応と既存 Fcitx との
組み合わせの確認が必要になる。別の OSK への置き換えは今回の目的より変更が大きい。

## 構成

- 共通の Home Manager program モジュールが wvkbd の起動と表示制御を担当する。
- 共通の NixOS feature モジュールが Fcitx アダプタとフォーカス連携を担当する。
- ホスト設定には `dotfiles.features.osk.enable` による有効化だけを置く。
  現在は NixOS と Home Manager で独立した設定のため、両側の有効化が必要になる。
- wvkbd は非表示で起動する。表示は SIGUSR2、非表示は SIGUSR1 を送り、
  既存の SIGRTMIN による手動切り替えと Noctalia のボタンを維持する。
- 制御対象は同じユーザーの `wvkbd.service` とし、systemd 経由でシグナルを送る。
- 起動と終了は既存の `graphical-session.target` に従う。

## 外部キーボード接続時の抑止

入力欄のフォーカス時に udev の input デバイス情報を読み、
`ID_INPUT_KEYBOARD=1` かつ `ID_BUS=usb` / `bluetooth` のキーボードがあれば
自動表示の SIGUSR2 を送らない。内蔵 i8042 キーボードやマウスは抑止条件に含めない。
`ID_INTEGRATION=internal` が付いた内蔵 USB キーボードなども除外する。
デバイス情報の取得に失敗した場合は、入力手段を失わないよう従来どおり表示する。

採用方式は既存の `ActivateCmd` から小さな表示判定スクリプトを呼ぶものとする。
常駐の着脱監視は、表示中に接続した瞬間も隠せるが、今回の自動表示抑止には不要なため追加しない。
外部キーボードを外した後は、次のフォーカスイベントで再び自動表示できる。
手動トグルとフォーカス解除時の非表示は維持する。
内蔵 USB キーボードに `ID_INTEGRATION=internal` が付かない構成では、
udev 側に識別情報を追加する必要がある。

## 対応範囲と検証

対象は既存の Linux / Wayland / Fcitx 構成とする。
自動表示の対象は Fcitx がフォーカスを検知できる入力欄とする。
物理キーボードの着脱を契機とする即時の表示変更、タブレットモード、
ログイン画面での表示は今回の範囲に含めない。

検証では、有効・無効時の設定と表示・非表示コマンドを確認する。
実際の入力欄への追従は GUI セッションでの確認が必要となる。
既存の `flake.lock` の競合と無関係な編集は保持する。

## 利用と実機確認

対象ホストの `home.nix` と `nixos.nix` の両方で、次を指定する。

```nix
dotfiles.features.osk.enable = true;
```

NixOS と Home Manager の設定を適用し、GUI セッションにログインし直す。
入力欄のフォーカスで表示、フォーカスを外すと非表示になることを確認する。
日本語入力と直接入力を切り替えても、入力欄にフォーカスしている間は表示を維持する。
アダプタには既存の約 400 ms の待ち時間がある。
`osk-toggle` と Noctalia のボタンによる手動切り替えも確認する。
その後のフォーカスイベントによる自動制御が、手動操作の状態を上書きする場合がある。

外部キーボード接続時の抑止は、NixOS の設定を再適用し、GUI セッションに
ログインし直して確認する。USB / Bluetooth キーボード接続中は入力欄を選んでも
自動表示されず、`osk-toggle` では表示できることを確認する。
キーボードを外して入力欄を選び直すと、自動表示が再開する。
表示中にキーボードを接続した瞬間の非表示は行わない。

## 検証結果

- 有効・無効の NixOS / Home Manager モジュール評価、生成された Fcitx 設定、
  全 Linux ホスト設定の有効化フラグとサービス・アダプタの整合性を確認した。
- 変更したアダプタのビルドと、変更ファイルの nixfmt / deadnix / statix を実行した。
- 実 Fcitx 5.1.23 の `Instance` と `InputContext` を使い、GUI なしで
  `focusIn()` / `focusOut()` を発生させた。同じ検証で既存アダプタは反応せず、
  変更したアダプタは表示・非表示のコールバックを順に実行した。
- wvkbd の画面表示と systemd 経由の信号送信は、設定適用後の GUI セッションで確認する。
- 外部キーボード判定は変更前に USB 接続中も表示信号が出ることを再現した。
  変更後は生成した表示コマンドを一時的な検証環境で実行し、USB / Bluetooth、
  内蔵 i8042 / USB、マウス、メディアキー、別デバイスの属性、デバイスなし、
  udev 失敗、属性値の境界、実機の W-CORNE 情報など 13 ケースを確認した。
- 抑止ヘルパーと実ホストの Fcitx 設定をビルドし、ShellCheck、モジュールの有効・無効、
  既存サービス・手動コマンドの維持、nixfmt / deadnix / statix と文書のフォーマットを確認した。
  独立したエージェントのレビューで修正が必要な指摘はなかった。
  外部キーボード抑止の設定適用と GUI での実際の着脱確認は未実施。
